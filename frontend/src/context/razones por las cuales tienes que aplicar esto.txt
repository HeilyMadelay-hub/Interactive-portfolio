```jsx
// src/context/LanguageContext.jsx
import { createContext, useContext, useState } from 'react';

const LanguageContext = createContext();

export const LanguageProvider = ({ children }) => {
    const [language, setLanguage] = useState('es'); // o detectar navegador

    return (
        <LanguageContext.Provider value={{ language, setLanguage }}>
            {children}
        </LanguageContext.Provider>
    );
};

export const useLanguage = () => {
    const context = useContext(LanguageContext);
    if (!context) {
        throw new Error('useLanguage debe usarse dentro de LanguageProvider');
    }
    return context;
};
```

---

## **Opción 1: Hook DENTRO del Context (lo que te recomendé)**

```
src/
└── context/
    └── LanguageContext.jsx  (Context + hook en el mismo archivo)
```

**Razón:**
- El hook `useLanguage()` está **100% acoplado** al `LanguageContext`
- No tiene sentido usar ese hook fuera del contexto de idiomas
- Es el patrón más común en React (ej: React Router hace `export const useNavigate` desde el mismo archivo del Provider)

---

## **Opción 2: Hook en archivo SEPARADO**

```
src/
├── context/
│   └── LanguageContext.jsx  (solo el Context)
└── hooks/
    └── useLanguage.js  (solo el hook)
```

**Razón:**
- Separación más estricta de responsabilidades
- Más fácil de encontrar si tienes muchos hooks custom
- Algunos equipos prefieren TODOS los hooks en `/hooks`

---

## **¿Cuál es mejor?**

**Para tu caso específico:** 

**Opción 1 (en el mismo archivo)** es más práctica porque:
- Solo tienes 1 hook relacionado con idiomas
- Reduces 1 import innecesario
- Es más cohesivo (Context y su hook juntos)

**PERO si prefieres Opción 2 (archivo separado):**

```jsx
// src/hooks/useLanguage.js
import { useContext } from 'react';
```
